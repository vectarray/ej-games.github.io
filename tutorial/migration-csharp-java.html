C# -> Java

This is a tutorial that is designed to help you migrate from C# to Java, or just find out the differences.

Intro

C# and Java are very similar in their general syntax. In fact, Java was even based on C#!! Which is really not true, because C# was originally created after Java.

C# was created and is still maintained by Microsoft.
Java was created by Sun Microsystems and is now maintained by Oracle. The easiest way of programming in Java is using the JDK (Java Development Kit).

Variables and Datatypes

Java is strong-typed, like C# - if you try to turn a string into an int, you will end up exploding.

And, from my experience of other peoples' Java code, the naming convention is camelCase for both variables and functions.

Functions and Classes

This is a function in Java: 
void funkyFunction():
	System.out.println("This is funky and swish!")

But, not as shown earlier, this is a class in Java: 
class CoolTerms
{
	String swish = "That's very swish!";

	void funkyFunction()
	{
		swish = "I prefer 'funky'";
	}
}

To return a value from a function, you can do this, just like in C#: 
String funkyFunction()
{
	return "I prefer 'funky'";
}

Collections in Java
Collections, like lists, arrays and dictionaries in Java, are similar in behaviour to ones in C#, but have different names and different architectures.

The equivalent of an array (like string[]) in C# is the same as in Java.

The equivalent of a list (like List<string>) in C#, is the same as in Java, but you can't create a List in the same way - instead, you either have to create an ArrayList<String> or a LinkedList<String>.
Both behave the same way, but an ArrayList acts just like an array with added methods to manage the list, and a LinkedList consists of a sort of "chain" of elements which are easy to add to each end, but harder to add into the middle. For example, a LinkedList has methods like addLast() and addFirst() which are obviously simpler to use than manually adding to the first item.
There are even more types of collection in Java:
Set
A set, like in Python if you are already familiar, contains unordered, unique items, like a bag of marbles containing just one of each colour.
HashSet
A HashSet, just like a set, is unordered and unique, but is "faster" and more efficient at controlling its elements.
TreeSet
A TreeSet contains unique elements like a Set, but sorts and orders its elements automatically.
LinkedHashSet
A LinkedHashSet is like a combination of a LinkedList and a HashSet. It's just like a HashSet, but is quicker at adding new elements to each "end" of the collection. This means they also retain the order depending on when each item is added.
Maps
A map is effectively a Dictionary from C#, and behaves effectively the same way - all keys must be unique, but values can be copies.

There is also:
  • HashMap: unordered, but quicker, like a HashSet
  • TreeMap: sorted by key, like a TreeSet
  • LinkedHashMap: sorted, but only by the order that items are inserted.
